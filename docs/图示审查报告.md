# 图示风格与建模审查

审查日期：2026-10-22。基线：`chao-shu/c-code-design-doc` 的提交 `044854c8f79d8a050c5a2cf1cbfa788ec80f0614`；本文记录在该版本上发现的问题、修订及验证。

## 结论

默认白底、蓝灰色系、中文无衬线字体和克制的节点强调，适合专业软件工程设计文档。七类样例的整体视觉已经合格；需要改进的主要是模型含义与跨图一致性。

修订后，所检查的 UML 图符合相应图型的基本语义，4+1 的关注点划分合理。构建输入和队列数据流明确作为自定义辅助图使用，不统称为标准 UML。文档以真实源码证据支撑结论，仍需对每次生成结果逐图复核。

| 维度 | 审查结果 | 关键依据 |
|---|---|---|
| 专业外观 | 通过本地预览检查 | 统一配色和字体层级；关键标签清楚；修改后的样例没有发现明显裁切、乱码或遮挡 |
| UML 语义 | 补强后通过本次人工核对 | 区分职责、文件、接口、生命线及自定义数据流；调用、返回、回调和状态变化分别表达 |
| 4+1 | 视角正确，补足跨视图映射 | 逻辑看职责，开发看组织与构建，进程看执行与协作，物理看部署，场景串起关键交互 |
| 简单易懂 | 保留单图单问题，减少混合关系 | 接口契约和证据放正文；图中保留关键交互；复杂关系通过场景或图后说明展开 |
| 源码准确性 | 测试样例范围内已核对 | 同步回调、函数返回码与完成结果、条件编译和未参与构建文件的区别正确 |

## 发现与修订

1. **文件与运行时参与者容易混淆。** 原规则允许直接把文件作为时序参与者。现改为“运行时角色 + 来源文件”，保留文件级模块标识，同时要求区分影响行为的不同实例与线程。逻辑视图先写职责，再映射文件，避免退化为目录图。
2. **自定义图例边界不够明确。** 构建输入箭头、队列数据流以及 `struct`、`thread` 等标签现明确说明含义，不将任意 PlantUML 语法视为标准 UML 元素。
3. **旧试跑把状态赋值画成自调用。** `busy = 1`、`last_result = -20` 没有发生函数调用。已要求使用 note 表达，并在历史试跑的人工复核副本中修正。
4. **样例间的一致性需要加强。** L1 的 `session_start()` 改为与 S1 一致的 `session_send()`；明确 L1/S1 相关，其他示例独立。正式文档增加“角色 → 职责/接口 → 文件 → 制品 → 执行上下文/部署”的映射检查。
5. **分支与状态迁移需更精确。** 时序样例先收到返回值再判断 `rc`；状态样例用明确的成功事件，区分事件、守卫与迁移动作。
6. **历史试跑逻辑图过宽。** 人工复核副本聚焦接口依赖，把完整契约与绑定说明移到正文/图例，回调交互由时序图展开；保留真实关系及其可追溯说明。

- 七张规范样例均通过 PlantUML 1.2025.0 检查并重新渲染；逐图查看布局，修改后再次检查受影响图。

## 核对依据

- [OMG UML 2.5.1](https://www.omg.org/spec/UML/2.5.1/PDF)：核对接口表示（10.4.4）、组件（11.6）、状态迁移（14.2）、消息（17.4.4.1）、生命线（17.12.17）及部署（19.2–19.4）的相关条款。
- [Kruchten 的 4+1 原始论文](https://www.cs.ubc.ca/~gregor/teaching/papers/4%2B1view-architecture.pdf)：用于核对各视图关注点、场景的串联作用和视图裁剪原则。保留五个视角的简短说明是本技能的学习文档约定，并非原论文要求固定五张图。
- [PlantUML 官方语法](https://plantuml.com/sequence-diagram)：用于核对图代码；语法可渲染与模型语义正确分别验收。
