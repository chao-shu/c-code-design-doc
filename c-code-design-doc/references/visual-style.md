# 专业工程图视觉规范

默认采用白底、深色文字、蓝灰色系的技术设计文档风格。以内容和结构支撑专业感：职责边界清楚，关系语义准确，阅读顺序明确。绘图前与 diagram-guide.md 一起读取；用户已有明确视觉规范时沿用用户规范。

## 内容与视觉同时验收

- 每图回答一个明确问题，标题用“图 L1｜主题（逻辑视图）”等形式；L/D/P/H/S 分别表示逻辑、开发、进程、物理、场景，其他图可用 C（上下文）或 T（数据/状态）。编号在同一文档内唯一。
- 图内放必要节点、关系和局部约束；图后用一两句话给出结论、配置/范围和证据编号。长解释、完整原型和来源表放正文。
- 颜色只帮助定位，不编码同步/异步、所有权或证据可信度。目标节点在文字中同时写“目标模块”或在图后明确指出；黑白阅读仍可理解。
- 文件、接口契约、数据对象、执行上下文与部署节点使用相应图元，不能为了形状统一而全部画成含义不明的矩形。

## 统一色板

| 用途 | 色值 | 使用规则 |
|---|---|---|
| 画布 | `#FFFFFF` | 全部图保持白底；不依赖宿主深色模式 |
| 正文与标题 | `#0F172A` | 深蓝灰，保持高对比 |
| 连线与边框 | `#475569` / `#64748B` | 细实线或对应 UML 关系的虚线 |
| 普通节点与注释 | `#F8FAFC` | 调用方、依赖、环境等采用中性底色 |
| 目标节点强调 | `#EFF6FF` | 配合“目标模块”文字，不为每个模块分配一种颜色 |
| 错误强调（可选） | `#B91C1C` | 只用于已确认错误路径，必须同时标注错误条件或错误码 |

避免彩虹配色、渐变、阴影、手绘风、装饰图标和无语义的粗箭头。保留 UML 原生组件、制品、节点等必要形状。不要将页面卡片样式套到工程图上。

## 字体、尺寸与留白

- 先为读者的渲染环境选定一套可用的中文无衬线字体，整篇统一。本包样式与预览使用已在预览环境确认存在的 `Microsoft YaHei`；在其他环境需确认字体，可换成已安装的 `Noto Sans CJK SC`。无法确认时使用逻辑字体 `SansSerif`，并在预览中检查中文回退效果；不假定字体存在，也不逐图混用。
- 默认节点文字 14，消息/边标签 13，图题 18，辅助图例 12。渲染器的单位和缩放可能不同，应以最终阅读效果为准。
- 节点标签优先两行：“文件名/实体名 + 简短职责”。长路径只在消除重名时保留必要部分；完整路径在正文映射。
- 结构图按语义选择从左到右或从上到下；调用方、目标模块、依赖的顺序保持一致。时序图从上到下表示时间，不改变真实执行次序换取对称布局。
- 节点间保持充足留白，线条尽量短且少交叉。不能改变边的语义以回避交叉；可换方向、调整分组或拆成两张图。布局用隐藏边时加注释说明其仅用于排版。
- 超宽图先缩短标签、减少重复接口文字，再分图；不通过整体缩小到难以阅读来勉强塞进页面。不要为追求全部直角而默认使用会造成标签冲突的连线设置。

## 每个图块的基础样式

将以下设置复制到每个独立 `@startuml` 图块内，再加入相关图型的样式和图内容。它是样式片段，不能单独当作完整图交付。不要使用远程主题或外部 include；图代码应随文档迁移。

```text
skinparam backgroundColor #FFFFFF
skinparam shadowing false
skinparam defaultFontName "Microsoft YaHei"
skinparam defaultFontSize 14
skinparam defaultFontColor #0F172A
skinparam titleFontColor #0F172A
skinparam titleFontSize 18
skinparam ArrowColor #475569
skinparam ArrowFontColor #334155
skinparam ArrowFontSize 13
skinparam ArrowThickness 1
skinparam NoteBackgroundColor #F8FAFC
skinparam NoteBorderColor #CBD5E1
skinparam NoteFontColor #475569
skinparam NoteFontSize 13
skinparam LegendBackgroundColor #FFFFFF
skinparam LegendBorderColor #FFFFFF
skinparam LegendFontColor #475569
skinparam LegendFontSize 12
```

图型的附加设置参照 [七类完整示例](diagram-guide.md#完整示例)。只复制本图需要的图型样式；目标元素用显式底色 `#EFF6FF`，并使用文字标识其角色。例如：

```text
component "src/session.c\n目标模块 · 会话状态" as M_SESSION #EFF6FF
```

序列图不添加无依据的激活区间或并发片段；C 数据结构图隐藏类图的默认 C 圆标，并保留 `<<struct>>` 等实际含义标注。函数指针字段用 `{field}` 明确表示字段，避免被按方法分组。

## 渲染后的通过条件

1. 中文无乱码或缺字，文字没有裁切、溢出、遮挡；标题、节点与辅助说明有明确层级。
2. 连线不穿过无关节点和文字；箭头终点、起点及对应标签可明确辨认。必要交叉不能让读者误判连接关系。
3. 正常阅读尺寸下，文件名、接口和条件不需要反复放大才能辨认；不存在靠微小字体容纳的“全系统大图”。
4. 同一文档的色板、字号体系、角色命名和图题样式一致；黑白查看仍能靠标签、形状和线型理解。
5. 每条关键关系都与源码或显式标注的未知项对应；原型、场景和错误码与正文一致。

若存在上述可见问题，先修正再交付。没有图像预览能力时仅可报告“样式已按规范生成，尚未完成视觉验收”。语法通过不等于视觉验收通过。

浏览器扩展可能重设主题、忽略部分 skinparam 或采用不同布局引擎。若目标扩展忽略样式，明确这一限制：先保留关系与可读性；需要本规范的完整视觉效果时，使用支持这些设置的 PlantUML 渲染器核对。不得声称不同引擎会产生像素一致的结果。
